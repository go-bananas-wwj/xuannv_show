### 1.3 为什么选择这些数据？

**核心原则：多源异构互补，而非单一数据**

| 设计动机 | 具体说明 |
|----------|----------|
| **光学+SAR互补** | Sentinel-2 提供10m多光谱，但受云雨影响；Sentinel-1 SAR 全天候工作，两者互补确保时序连续性 |
| **多分辨率融合** | S2(10m) + Landsat(30m) + 高分(更高分辨率) 组合，既保证覆盖范围又有细节 |
| **多维度信息** | 光谱(S2) + 微波(S1) + 地形(DEM) + 气候(MODIS) = 更完整的地表表征 |
| **长时序覆盖** | 2023-2025 多季节数据，捕捉物候变化（春生夏长秋收冬藏） |
| **文本对齐** | AEF使用Wikipedia文本进行对比学习，让嵌入空间具备语义可解释性 |

**为什么不选其他数据？**
- **不用纯RGB**（如DINOv3用的Maxar航拍）：RGB缺少近红外、SWIR等关键波段，无法区分植被健康和含水量
- **不用单一传感器**：单传感器无法应对云层遮挡，且信息维度不足
- **不用更粗分辨率**：30m+分辨率会丢失城市细节、农田边界等关键信息

## 问题2：嵌入模型怎么训练？Patch分辨率怎么定的？用了什么时相？

### 2.1 模型架构（AEF改进版）

```
qwen_v5_mixed_scale.yaml
  → embedding_dim: 128
  → precision_dim: 256 (STP主干通道)
  → stem_dim: 128 (传感器编码器)
  → num_blocks: 6 (STP Block)
  → num_heads: 8 (Attention heads)
```

**训练架构**：Space-Time-Precision (STP) Encoder + VMF Bottleneck

**Embedding 输出流程**：
1. STP主干输出 `summary_map`: `[B, 256, H, W]`
2. 经过 `Conv2d(256→128, 1×1)` 得到 `pre_norm_map`
3. L2归一化 + Von Mises-Fisher (VMF) 采样
4. 最终输出 `embedding_map`: `[B, 128, H, W]`（空间密集嵌入）

> AEF原始论文使用 **64维**，但我们的改进版（v5_mixed_scale）扩展到了 **128维**。

### 2.2 训练方法（AEF原始）

**教师-学生自编码器 + 文本对齐网络**：

1. **Teacher Network**: 处理完整、未扰动的输入影像
2. **Student Network**: 同架构，但从被扰动/不完整的输入产生相同embedding
3. **Text Alignment Network**: 接收Wikipedia文本描述并生成embedding

**4种损失函数**：
- **Reconstruction Loss**: 重建输入影像
- **Consistency Loss**: 教师-学生embedding一致性
- **Text Contrastive Loss**: 影像-文本对比对齐
- **Batch Uniformity Loss**: 将embedding约束到128维球面均匀分布

### 2.3 Patch分辨率：为什么是1280m×1280m @ 20m？

| 参数 | 数值 | 来源 |
|------|------|------|
| 单Patch实际尺寸 | **1280m × 1280m** | patches_meta.json |
| 空间网格 | **64 × 64** | .npy embedding shape |
| 有效分辨率 | **20m/pixel** | 1280m / 64px |
| 坐标系 | EPSG:32652 (UTM 52N) | patches_meta.json |

**为什么是20m而不是AEF标准的10m？**

**澄清**：模型输入层使用统一的 128×128 @ ~10m 像素网格（通过 resize 对齐），但模型内部的 STP Encoder 在 stem 层通过 stride=2 将空间分辨率下采样到 64×64，因此最终 embedding 的空间分辨率是 20m/像素。这是模型架构设计（编码器下采样），不是数据分辨率选择。

**为什么是1280m×1280m？**

- 128×128 像素网格适配深度学习架构的下采样（128→64→32→16→8→4，通过 stem 的 stride=2）
- 1280m 的地面覆盖足够包含：农田地块、建筑群、河流段落、森林斑块等中等尺度地物
- 所有数据源统一 resize 到 128×128，保证多源输入在空间上对齐

### 2.4 时相选择：为什么是2023-2025？

| 设计考量 | 说明 |
|----------|------|
| **覆盖多季节** | 2023-2025 包含3个完整年度，春/夏/秋/冬四季都有观测 |
| **月度embedding** | 每月生成一个embedding，捕捉物候变化（如植被绿度变化） |
| **最新数据** | 2025年数据确保模型训练在最新卫星影像上 |
| **时序连续性** | Sentinel-2 5天重访周期，确保大部分时间有可用数据 |

**AEF的连续时间特性**：
AEF支持**连续时间**（continuous time），可为任意日期范围生成embedding，即使没有直接卫星影像也可通过插值推断。这是AEF相比其他基础模型的核心优势之一。

## 问题3：为什么是128维？而不是64维或32维？

### 3.1 维度对比：主流遥感基础模型

| 模型 | 维度 | 设计动机 | 来源 |
|------|------|----------|------|
| **AEF (原始)** | **64** | 极致压缩+行星尺度部署 | Google DeepMind |
| **OlmoEarth-nano** | **128** | 平衡效率与表达力 | AllenAI |
| **TESSERA (产品)** | **128** | 像素级嵌入压缩输出 | arXiv 2506.20380 |
| **SatCLIP** | **256** | 空间-图像对比学习 | Microsoft |
| **DINOv3 ViT-L** | **1024** | 通用视觉先验 | Meta |
| **Prithvi-EO-2.0** | **1280** | NASA多光谱预训练 | NASA |

### 3.2 AEF为什么选择64维？

AEF论文 **S21.3 Bottleneck Characteristics** 中的消融实验：

- **D=64, κ=8×10³**（von Mises-Fisher分布集中度）是最优平衡点
- 更大legend（更多类别）的数据集倾向于更高维度
- 更noisy的bottleneck在小样本场景（1-shot, 10-shot）中表现更好
- **64维是在存储效率、下游任务性能和embedding空间平滑度之间的最优平衡**

**存储成本对比**（全球1年数据）：

| 模型 | 维度 | 每像素大小 | 全球年数据量 | S3年成本 |
|------|------|-----------|-------------|---------|
| DINOv3 ViT-L | 1024 | 4096 bytes | 6.1 PB | $1.7M |
| TESSERA | 512 | 2048 bytes | 3.1 PB | $847K |
| OlmoEarth | 128 | 512 bytes | 768 TB | $212K |
| **AEF (int8)** | **64** | **64 bytes** | **96 TB** | **$26K** |

> AEF的64维int8表示将全球数据控制在96TB，是DINOv3的1/64。这对**行星尺度部署**至关重要。

### 3.3 为什么我们的改进版是128维？

**诚实回答：目前尚未进行系统的消融实验，选择128维是基于以下判断**

| 对比维度 | AEF原始 | 我们的改进版 |
|----------|---------|-------------|
| **应用场景** | 全球年度map | 区域级展示平台（哈尔滨） |
| **存储约束** | 极严格（全球PB级） | 宽松（单区域GB级） |
| **下游任务** | 广泛的全球分析 | 特定的5个监测任务 |
| **精度要求** | 平衡精度与成本 | 优先精度 |

**当前选择128维的原因**：

1. **捕捉更多语义信息**：直觉上更高维度能编码更丰富的地表特征，为下游任务提供更多判别信息
2. **与业界趋势一致**：OlmoEarth-nano（128维）和TESSERA（128维产品输出）都选择了128维
3. **技术实现简单**：模型配置中 `embedding_dim: 128`，通过 `Conv2d(256→128)` 实现，相比64维只多了一层卷积参数

**后续计划**：将进行消融实验，测试64维、32维甚至16维的效果

**外部证据支持**：
- [Compressing Earth Embeddings](https://geospatialml.com/posts/compressing-earth-embeddings/) 发现：int8量化几乎无损（与float32统计不可区分），PCA(64)+int8在DINOv3(1024维)上仅损失1.4%准确率
- [TerraBit](https://geospatialml.com/posts/terrabit/) 发现：Clay v1.5(1024维)的本征维度仅13-17，维度减半不会大幅损失性能
- 这些研究表明，高维嵌入存在大量冗余，压缩到更低维度后仍保持很高的任务性能

### 3.4 128维 vs 64维/32维的效果区别

| 维度 | 优势 | 劣势 | 适用场景 |
|------|------|------|----------|
| **32维** | 存储极小 | 信息容量不足，复杂地类区分困难 | 粗略概览、移动端 |
| **64维** | AEF官方最优；存储效率高；信息紧凑 | 对复杂下游任务可能不足 | 全球部署、大规模推理 |
| **128维** | 更丰富的特征子空间；MLP性能提升显著；与业界主流一致 | 存储×2 | 区域级平台、高精度任务 |
| **256+维** | 表达能力最强 | 存储成本高；可能过拟合 | 通用视觉模型、研究场景 |

**我们的选择验证**：
- Building Extraction: Linear Probe F1=0.30 → MLP F1=0.96（128维提供足够非线性特征）
- JRC Water: Linear Probe F1=0.79 → MLP F1=0.86
- 说明128维的embedding空间有足够的判别力，MLP能挖掘Linear Probe无法捕捉的模式

## 问题4：从128维中选3维做假彩色可视化

### 4.1 当前方案：PCA-RGB

项目已实现的 `generate_embedding_tiles.py` 使用全局PCA：
- 128维 → PCA(3维) → 归一化 → RGB
- 优点是最大化方差保留，计算简单
- 缺点是"固定"的3维组合，不能反映特定语义

### 4.2 新增方案：交互式维度选择

**方案A：手工语义维度选择**

参考AlphaEarth的"维度功能字典"研究，通过线性探测分析各维度对不同地类的敏感性，推荐几组"语义假彩色"：

| 预设名称 | 选择维度 | 适用场景 |
|----------|---------|----------|
| **植被模式** | 选NDVI敏感维度组合 | 突出森林、农田、草地差异 |
| **水体模式** | 选NDWI敏感维度组合 | 突出河流、湖泊、湿地 |
| **建筑模式** | 选Built-up敏感维度组合 | 突出城市区域 |
| **变化模式** | 选时序差异最大维度 | 突出两期变化 |

**方案B：交互式滑块选择**

前端提供3个滑块（各1-128），用户可自由组合任意3个维度：
- 实时预览选中的3维组合效果
- 类似 Photoshop 通道混合器

**方案C：自动语义推荐**

根据当前patch的地类分布，自动推荐最能区分地物的3个维度组合

### 4.3 实现建议

推荐 **方案A（预设语义模式）+ 方案B（交互滑块）** 结合：
- 提供4-6个"语义预设"（植被/水体/建筑/变化等）
- 同时支持用户自定义选择任意3维
- 这比纯PCA更有"可解释性"和"探索性"

## 问题5：128维向量的分布和每一维的意义

### 5.1 实际数据统计

对50个patch的聚合分析：

| 指标 | 数值 |
|------|------|
| 总体均值 | -0.0006（接近0） |
| 总体标准差 | 0.0798 |
| 各维度均值范围 | [-0.0960, 0.0607] |
| 各维度标准差范围 | [0.0764, 0.0917] |
| 取值范围 | [-0.4478, 0.4821] |

**分布特征**：
- 接近零均值，符合batch uniformity loss的设计（约束到球面均匀分布）
- 各维度方差相对均衡，没有"死维度"（所有维度std都在0.076-0.092之间）
- 数值范围适中，适合int8量化（AEF官方使用int8量化）

### 5.2 每一维是否有意义？

**核心结论：单维度通常没有直接语义标签，但维度组合编码了物理属性**

**证据1：AlphaEarth维度功能字典**（Benavides et al., 2025）
- 在全球范围执行了 >130,000 次独立二分类实验
- 将64维按功能分为4类：
  - **Specialist**: 对单一地类（如Tree cover、Water）高度敏感
  - **Low-generalist**: 对2-3种地类有贡献
  - **Mid-generalist**: 对约半数地类有贡献
  - **High-generalist**: 对所有地类均有判别力

**证据2：流形几何分析**（Barrett et al., 2026）
- 嵌入流形是**非欧的、弯曲的**
- 局部本征维度约10，全局有效维度13.3
- **概念方向在流形不同位置会旋转**，不存在全局最优的3个维度

**证据3：EarthPT物理连贯性**
- 将1280维嵌入投影到2D，用NDVI/NDWI等着色
- 发现嵌入空间呈现**与物理指标高度一致的组织结构**
- 但语义是"分布式"编码在高维组合中的

### 5.3 如何可视化128维分布？

**方案1：维度-地类关联热图**
- 用线性探测分析128维中每一维对各下游任务地类的特征重要性
- 前端展示128×N的热图（N=地类数），颜色表示重要性

**方案2：UMAP 2D投影 + 地类着色**
- 将每个patch的全局平均embedding（128维向量）用UMAP投影到2D
- 用WorldCover/Dynamic World地类着色
- 验证"同类地物是否在嵌入空间聚集"

**方案3：维度分布直方图**
- 展示128维中每一维的数值分布直方图
- 对比不同地类（如水体vs建筑）在各维度上的分布差异

**方案4：时序变化轨迹**
- 对同一patch的5个月份embedding，在UMAP空间中绘制时间轨迹
- 展示季节性变化在嵌入空间中的"运动路径"

## 问题6：下游任务有哪些？效果如何？

### 6.1 当前接入的下游任务

| # | 任务 | 类型 | 类别数 | 数据源 | Head类型 |
|---|------|------|--------|--------|----------|
| 1 | **变化检测** | 语义分割 | 2（变化/无变化） | 两期S2对比 | ChangeDetectionHeadV3 (PyTorch) |
| 2 | **WorldCover土地覆盖** | 多分类 | 11类 | ESA WorldCover | Linear Probe / MLP |
| 3 | **Dynamic World土地利用** | 多分类 | 9类 | Google Dynamic World | Linear Probe / MLP |
| 4 | **JRC水体提取** | 二分类 | 2（水体/非水体） | JRC Global Surface Water | Linear Probe / MLP |
| 5 | **建筑提取** | 二分类 | 2（建筑/非建筑） | WorldCover Built-up | Linear Probe / MLP |

### 6.2 当前效果指标

| 任务 | Head | BA | F1 | 评价 |
|------|------|-----|-----|------|
| 变化检测 | PyTorch Head | — | AUC=0.886 | ✅ 优秀 |
| WorldCover | Linear Probe | 0.525 | 0.474 | ⚠️ 有提升空间 |
| Dynamic World | Linear Probe | 0.414 | 0.406 | ⚠️ 有提升空间 |
| Dynamic World | **MLP** | **0.502** | **0.496** | 📈 提升显著 |
| JRC Water | Linear Probe | 0.711 | 0.790 | ✅ 良好 |
| JRC Water | **MLP** | **0.822** | **0.862** | 📈 优秀 |
| Building | Linear Probe | 0.570 | 0.295 | ⚠️ 偏低 |
| Building | **MLP** | **0.957** | **0.956** | 📈 接近完美 |

### 6.3 效果分析

**为什么不同任务效果差异大？**

1. **变化检测 (AUC 0.886)**：
   - 使用专用PyTorch Head（非Linear Probe），有非线性建模能力
   - 500-shot训练，数据量充足
   - 变化检测是embedding的"天然强项"（直接比较两期向量差异）

2. **JRC Water (F1 0.862)**：
   - 水体在光谱上特征明显（近红外强吸收）
   - 二分类问题相对简单
   - MLP有效去除了噪声

3. **Building (F1 0.956)**：
   - MLP大幅提升说明建筑特征在embedding空间中有非线性可分模式
   - 但Linear Probe效果差（0.295），说明建筑特征不是线性可分的
   - 去噪后处理（binary opening + 连通域过滤）进一步提升了视觉效果

4. **WorldCover/Dynamic World (F1 0.47-0.50)**：
   - 多分类（9-11类）比二分类困难
   - 某些类别在光谱上相似（如灌木vs森林、裸地vs建筑）
   - 需要更复杂的Decoder（如UPerNet）而非Linear Probe/MLP
   - 参考PANGAEA基准，多分类任务通常需要专门的分割Decoder

### 6.4 与业界对比

| 模型 | EuroSAT (10类) | 方法 |
|------|---------------|------|
| AEF (64维) | 95.4% | Linear Probe |
| OlmoEarth (128维) | 96.5% | Linear Probe |
| DINOv3 (1024维) | 98.0% | Linear Probe |
| AEF压缩后(64维int8) | 96.4% | Linear Probe |

我们的Dynamic World（9类）和WorldCover（11类）使用Linear Probe只有40-50% BA，说明：
1. 哈尔滨区域的地物复杂度高于EuroSAT
2. 我们的embedding可能还有提升空间
3. 需要更强的下游Head（如UPerNet）而非Linear Probe

## 总结与前端展示建议

### 领导问题的核心答案

| 问题 | 一句话答案 |
|------|-----------|
| 1. 输入数据 | 多源异构（S2+S1+Landsat+高分+MODIS+DEM），互补覆盖光谱/微波/时序/地形 |
| 2. 训练方式 | STP Encoder + VMF Bottleneck，教师-学生自编码器+文本对齐+球面均匀约束 |
| 3. 128维原因 | AEF原始64维为行星存储优化；我们128维为区域精度优化，MLP显著提升下游效果 |
| 4. 假彩色 | 在现有PCA-RGB基础上，增加"语义预设模式"（植被/水体/建筑）+ 交互滑块选维 |
| 5. 维度意义 | 单维无语义，组合编码物理属性；可通过线性探测分析维度-地类关联热图 |
| 6. 下游效果 | 5大任务：变化检测(AUC 0.89)、建筑(F1 0.96)、水体(F1 0.86)、土地覆盖(待提升) |
